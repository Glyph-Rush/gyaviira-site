# Gyaviira Engine: Supabase Setup Guide

This document provides a consolidated set of SQL commands and configurations required to initialize the Gyaviira platform backend. Run these commands in your Supabase **SQL Editor**.

## 1. Core Identity: Profiles Table
Stores public user data linked to authentication.

```sql
-- Create profiles table
CREATE TABLE profiles (
  id UUID REFERENCES auth.users NOT NULL PRIMARY KEY,
  email TEXT,
  username TEXT UNIQUE,
  profile_pic TEXT,
  bio TEXT,
  role TEXT DEFAULT 'user', -- 'user', 'admin', or 'founder'
  is_banned BOOLEAN DEFAULT false,
  is_verified BOOLEAN DEFAULT false,
  preferences JSONB DEFAULT '{"musicAlerts": false, "communityMentions": false, "storeExclusives": false}',
  created_at TIMESTAMP WITH TIME ZONE DEFAULT timezone('utc'::text, now()) NOT NULL
);

-- Enable RLS
ALTER TABLE profiles ENABLE ROW LEVEL SECURITY;

-- Policies
CREATE POLICY "Public profiles are viewable by everyone." ON profiles FOR SELECT USING (true);
CREATE POLICY "Users can update own profile." ON profiles FOR UPDATE USING (auth.uid() = id);
CREATE POLICY "Users can insert their own profile." ON profiles FOR INSERT WITH CHECK (auth.uid() = id);
```

## 2. Community Layer: Messages Table
Stores all encrypted transmissions (chat messages).

```sql
CREATE TABLE messages (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  channel TEXT NOT NULL,
  user_id UUID REFERENCES profiles(id) NOT NULL,
  username TEXT NOT NULL,
  text TEXT NOT NULL,
  profile_pic TEXT,
  is_admin BOOLEAN DEFAULT false,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT timezone('utc'::text, now()) NOT NULL
);

-- Enable RLS
ALTER TABLE messages ENABLE ROW LEVEL SECURITY;

-- Policies
CREATE POLICY "transmissions_are_public" ON messages FOR SELECT USING (true);
CREATE POLICY "authenticated_post_access" ON messages FOR INSERT WITH CHECK (auth.role() = 'authenticated');
CREATE POLICY "steward_delete_access" ON messages FOR DELETE USING (auth.uid() = user_id);
```

## 3. Dynamic Infrastructure: Channels Table
Manages the frequencies available in the Community Chat.

```sql
CREATE TABLE public.channels (
    id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
    slug TEXT UNIQUE NOT NULL,
    name TEXT NOT NULL,
    is_restricted BOOLEAN DEFAULT false, -- If true, only admins post
    created_at TIMESTAMP WITH TIME ZONE DEFAULT timezone('utc'::text, now()) NOT NULL
);

-- Enable RLS
ALTER TABLE public.channels ENABLE ROW LEVEL SECURITY;

-- Policies
CREATE POLICY "channels_viewable_by_all" ON public.channels FOR SELECT USING (true);

CREATE POLICY "admin_and_founder_management" 
ON public.channels FOR ALL 
USING (
  EXISTS (
    SELECT 1 FROM public.profiles 
    WHERE profiles.id = auth.uid() 
    AND profiles.role IN ('admin', 'founder')
  )
);

-- Seed Initial Frequencies
INSERT INTO public.channels (slug, name, is_restricted) VALUES 
('creative-frequency', 'Creative Frequency', false),
('announcements', 'Announcements', true),
('general-vibe', 'General Vibe', false)
ON CONFLICT (slug) DO NOTHING;
```

## 4. Automation: Auth Triggers
Syncs Supabase Auth users with the public `profiles` table automatically.

```sql
-- Function to handle new user signup
CREATE OR REPLACE FUNCTION public.handle_new_user()
RETURNS TRIGGER AS $$
BEGIN
  INSERT INTO public.profiles (id, email, username, role)
  VALUES (new.id, new.email, new.raw_user_meta_data->>'username', 'user');
  RETURN new;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

-- Trigger on auth.users insert
CREATE TRIGGER on_auth_user_created
  AFTER INSERT ON auth.users
  FOR EACH ROW EXECUTE PROCEDURE public.handle_new_user();
```

## 5. Media: Storage Buckets
Set up a public bucket for profile picture storage.

```sql
-- Create 'avatars' bucket
INSERT INTO storage.buckets (id, name, public) VALUES ('avatars', 'avatars', true);

-- Policies
CREATE POLICY "Avatar images are publicly accessible." ON storage.objects FOR SELECT USING (bucket_id = 'avatars');
CREATE POLICY "Users can upload their own avatar." ON storage.objects FOR INSERT WITH CHECK (bucket_id = 'avatars' AND auth.role() = 'authenticated');
```

## 6. Real-time Configuration
To ensure live dashboard stats and instant channel updates work, perform these steps in the Supabase Dashboard:

1.  Navigate to **Database** -> **Replication**.
2.  In the `supabase_realtime` publication, click **Source**.
3.  Add the following tables to the publication:
    *   `messages`
    *   `channels`
4.  This enables the application to listen for `INSERT`, `UPDATE`, and `DELETE` events on these tables.

---
**Note:** All administrative UI (Channel management, Live stats) in the `AdminPanel` depends on the `channels` table and Real-time being correctly enabled.
